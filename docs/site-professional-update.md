# Personal website: navigation, discovery and presentation

This update targets the personal academic website at `https://chengadi.science`.
The site remains an Astro static build deployed through the existing GitHub
Pages workflow.

## What changed

### Shared presentation and navigation

- A consistent header, compact portrait mark, clearer navigation and organized
  footer give visitors direct routes to the academic profile, projects,
  teaching, community, CV and contact pages.
- Mobile navigation has explicit expanded state, current-section markers,
  Escape handling and focus restoration. Selecting a destination or returning
  to a wide viewport closes the mobile menu.
- A white/paper background control stores its preference on the current
  device. The early head script restores a saved preference before the main
  interface initializes. Blocked browser storage does not prevent changing the
  current page appearance or using navigation and search.
- Shared styles include responsive layouts, visible keyboard focus and reduced
  motion handling. These are implementation changes,
  not a claim of a completed accessibility certification.
- The homepage now offers explicit routes for students, public projects and
  community visitors, and highlights the existing QBRL and QEGK public project
  entries. Current courses and both language versions of the activity
  collections are easier to reach.

### Website search

`src/data/siteDiscovery.ts` generates an explicit public metadata index. The
inspected build contains 74 entries across Teaching, Projects, Community and
Academic, including all 13 current linear algebra tutorials.

The global search dialog fetches `/search-index.json` only when first opened,
then filters the index locally. It supports English and Hebrew keywords,
keyboard opening with Ctrl/Command + K, Arrow Down to the first result, Escape
to close, focus restoration and a link to all matching results. It can retry a
failed load and uses the latest input if someone types while loading.

The `/search` directory renders all entries in the HTML. With JavaScript it
adds topic search, category selection, result counts, empty-state guidance,
reset and shareable submitted query URLs. Without JavaScript the full resource
directory remains available.

Search is built from published page metadata. It does not fetch Student Hub
messages, private requests, accounts or access codes. Draft collection items,
placeholder pages and direct file URLs are excluded. The client discards
nonlocal or invalid result URLs and renders result text literally.

### Teaching and current tutorials

- Current 2026–2027 course resources are clearly separated from the recording
  and practice-sheet archive.
- All three existing course IDs retain their classroom entry links.
- The 13 current tutorials can be found by number or topic, with clear/reset
  controls and no-results guidance.
- Each tutorial retains its original Hebrew PDF page destination and offers
  separate English and Hebrew activity links.
- Tutorial and practice-sheet deep links reveal a destination even if a local
  filter was hiding it, including repeated links to the current hash.
- Empty recording or material counts are no longer presented as useful course
  statistics. Existing archive render paths and PDF gate configuration remain.

### Public projects, research and contact

- The project index includes text search, availability filters, result counts,
  direct project anchors and clearer access to existing code and previews.
- Research uses a clearer affiliation layout with profile, CV, public-work and
  enquiry links. An empty publication collection does not create publications.
- Contact offers distinct routes for general enquiries, anonymous course
  discussions, private course logistics and returning to private replies.
- The existing Student Hub remains the communication mechanism. This update
  does not add email delivery or change its backend.

### Discovery metadata

- Pages share canonical, Open Graph and Twitter metadata using the existing
  local portrait asset.
- `/sitemap.xml` lists 39 unique public page URLs in the inspected build;
  `robots.txt` declares the sitemap. These are regenerated by the static build.
- A useful `404.html` page supplies routes back into the site.
- Search, 404 and the exact empty/coming-soon pages `/library`, `/materials` and
  `/digital-courses` are marked `noindex, follow` and omitted from the sitemap.
  This rule does not blanket-exclude future published material detail pages.
- `public/CNAME` carries the existing custom domain into the deployment.

## Preserved content requirements

The public interface remains English, with Hebrew and English teaching
activities offered through the established language routes. Student-written
notes and activity state retain their existing storage and language-switch
behavior.

The profile, homepage, research page and CV continue to identify the M.Sc. in
Physics under Prof. Yaron Oz without disclosing the thesis topic. The CV remains
a readable web page and its removed PDF is not restored.

The English-course syllabus retains its corrected grading rules: WeBWorK is
practice only and has no grade or protective component. The written-homework
and examination rules remain unchanged. The existing event announcement
statuses and reading selection are retained.

The discovery test harness removes parsed `noscript` fallbacks before manually
executing scripts, so jsdom's disabled-scripting parse mode does not activate
fallback CSS during JavaScript interaction checks.

### Reproduce the checks

Use the repository's locked dependencies and the Node version required by
`package.json`. Install jsdom in an isolated QA directory and point
`PORTAL_QA_ROOT` to that directory. The verification run used
`/tmp/chengadi-qa`; jsdom was not added as a website dependency.

```sh
node node_modules/astro/bin/astro.mjs build
PORTAL_QA_ROOT=/tmp/chengadi-qa node scripts/tests/site-release.mjs
PORTAL_QA_ROOT=/tmp/chengadi-qa node scripts/tests/portal-dom.mjs
PORTAL_QA_ROOT=/tmp/chengadi-qa node scripts/tests/linear-lab-dom.mjs
PORTAL_QA_ROOT=/tmp/chengadi-qa node scripts/tests/linear-language.mjs
PORTAL_QA_ROOT=/tmp/chengadi-qa node scripts/tests/site-discovery.mjs
node scripts/tests/linear-lab-math.mjs
python public/files/linear-algebra-lab/verify_examples.py
```

## Verification limits

No graphical browser review or screenshot inspection was performed for this
update. DOM checks establish the tested interaction and markup behavior; they
do not establish final visual layout, native dialog behavior on every browser,
real-device accessibility or Core Web Vitals. No performance scores or formal
WCAG conformance are claimed.

The portal suite uses mocked API responses. It does not constitute a new live
backend authorization audit. No real messages or invitations were sent during
verification. Public external resource destinations were preserved, not
exhaustively rechecked for current availability.

The build continues to report the pre-existing absent/empty `research`,
`communityGallery` and `updates` collections. Their missing content was not
filled with invented material. Event-date classification and discovery entries
update when the static website is rebuilt.
